# Chop روی Vercel

این پورت از همون پنل Chop است، منتها به‌جای Cloudflare Workers روی
Vercel Functions (با WebSocket بومی Beta که ۲۲ ژوئن ۲۰۲۶ منتشر شد) اجرا
می‌شه. قبل از دیپلوی این‌ها رو حتماً بخون — چند تفاوت واقعی با نسخه‌ی
Cloudflare داره که نمی‌شه دورشون زد (محدودیت خودِ پلتفرمه، نه این کد).

## تفاوت‌های مهم با نسخه‌ی Cloudflare

1. **هر اتصال VLESS حداکثر ۳۰ دقیقه باز می‌مونه** (سقف Beta برای WebSocket
   روی Vercel، فقط پلن Pro/Enterprise؛ پیش‌فرض بدون تنظیم ویژه فقط ۵
   دقیقه‌ست). بعدش کلاینت باید خودش reconnect کنه. بیشتر کلاینت‌های VLESS
   (v2rayNG، NekoBox، Streisand، ...) این کارو خودکار انجام می‌دن، ولی یعنی
   یه قطعی چندثانیه‌ای هر نیم‌ساعت، نه یه تونل کاملاً پیوسته مثل Cloudflare.
2. **بدون Durable Object.** حالت (کانفیگ‌ها، مصرف، لاگ‌ها، تنظیمات) توی
   Redis نگه داشته می‌شه، نه storage محلیِ سراسری. باید یه Redis وصل کنی
   (پایین توضیح داده شده).
3. **قابلیت «آی‌پی تمیز» فقط وقتی معنی داره که دامنه‌ی همین دیپلوی از
   طریق Cloudflare (ابر نارنجی) جلوی Vercel پراکسی شده باشه.** این ترفند
   مال روتینگ SNI در شبکه‌ی Cloudflare است؛ اگه مستقیم از دامنه‌ی خودِ
   Vercel استفاده می‌کنی (بدون Cloudflare جلوش)، اسکنر/تست هیچ IPای پیدا
   نمی‌کنه — طبیعیه، نه باگ. اگه این حالتو داری، همون تنظیمات پیش‌فرض
   کانفیگ (بدون آی‌پی تمیز، فقط دامنه‌ی خودت) رو استفاده کن.
4. **صورت‌حساب Vercel بر پایه‌ی Active CPU/Function invocations است**، نه
   سقف ثابت روزانه مثل Cloudflare. برای یه پروکسیِ پرترافیک، این می‌تونه
   هزینه‌ی غیرقابل‌پیش‌بینی‌تری نسبت به Cloudflare داشته باشه — قبل از
   استفاده‌ی جدی، حتماً قیمت‌گذاری فعلی Vercel Functions رو چک کن.

## کاهش پینگ / تأخیر

مهم‌ترین عاملی که روی پینگ اثر می‌ذاره، فاصله‌ی فیزیکیِ **ریجن اجرای
تابع** (نه دامنه یا CDN) تا کاربرهای واقعیه. پیش‌فرض Vercel ریجن
`iad1` (واشینگتن، آمریکا) است که برای کاربرهای خاورمیانه/ایران فاصله‌ی
زیادی داره. توی `vercel.json` این پروژه الان روی `fra1` (فرانکفورت)
تنظیم شده که معمولاً نزدیک‌ترین هاب به خاورمیانه‌ست. اگه کاربرهای
اصلیت جای دیگه‌ان، `regions` رو عوض کن:

| ریجن | کد |
|---|---|
| فرانکفورت (اروپا/خاورمیانه) | `fra1` |
| دوبلین | `dub1` |
| بمبئی | `bom1` |
| سنگاپور | `sin1` |
| توکیو | `hnd1` |
| واشینگتن (پیش‌فرض) | `iad1` |

روی پلن Hobby فقط یه ریجن قابل انتخابه (ولی همون یکی رو می‌شه عوض
کرد)؛ روی Pro/Enterprise می‌شه چندتا هم‌زمان گذاشت. بعد از تغییر،
دوباره دیپلوی کن تا اعمال بشه.



- یه اکانت Vercel با پلن **Pro یا Enterprise** (برای WebSocket بیشتر از ۵
  دقیقه).
- یه دیتابیس Redis. ساده‌ترین راه: از **Vercel Marketplace → Redis** یکی
  وصل کن (Upstash یا مشابه). بعد از وصل کردن، مقدار `REDIS_URL` رو از
  تنظیمات همون یکپارچه‌سازی بردار.

## Environment Variables

توی تنظیمات پروژه‌ی Vercel این‌ها رو ست کن:

| متغیر | اجباری | توضیح |
|---|---|---|
| `REDIS_URL` | بله | آدرس اتصال Redis (چیزی شبیه `redis://default:...@...:6379`) |
| `ADMIN_PASS` | بله | رمز ورود پنل ادمین |
| `ADMIN_USER` | خیر | پیش‌فرض `admin` |
| `SESSION_SECRET` | بله (برای امنیت واقعی) | یه رشته‌ی تصادفی طولانی برای امضای کوکی سشن |
| `PUBLIC_HOST` | خیر | اگه دامنه‌ی سفارشی داری و می‌خوای لینک‌ها/سابسکریپشن دقیقاً همون دامنه رو نشون بدن |

## دیپلوی

```bash
npm install
vercel deploy --prod
```

بعد از اولین دیپلوی:
1. توی Vercel Dashboard → پروژه → Settings → Functions، مطمئن شو
   **Fluid Compute** فعاله (پیش‌فرض پروژه‌های بعد از ۲۳ آوریل ۲۰۲۵) و
   گزینه‌ی «Extended function duration» (Beta) رو فعال کن تا سقف ۳۰
   دقیقه‌ای واقعاً اعمال بشه — این تنظیم ممکنه جدا از `vercel.json` هم
   لازم باشه؛ مستندات فعلی WebSocketهای Vercel رو چک کن چون این قابلیت
   هنوز Beta است و ممکنه تغییر کنه.
2. با مرورگر برو به `https://<دامنه‌ت>/` و با `ADMIN_USER`/`ADMIN_PASS`
   وارد شو.
3. یه کانفیگ بساز و لینک `vless://` رو با یه کلاینت تست کن.

## ربات تلگرام

بخش ربات تلگرام (webhook ساده‌ی HTTP، نه WebSocket) بدون هیچ تغییری کار
می‌کنه — از پنل → تب «ربات تلگرام» → توکن رو بذار و فعالش کن، دقیقاً مثل
نسخه‌ی Cloudflare.

## چیزی که عمداً حذف/تغییر نکردیم

بقیه‌ی منطق (پنل، ساخت لینک، محدودیت ترافیک/IP، بکاپ/بازیابی، بات
تلگرام) عیناً همون کدِ نسخه‌ی Cloudflare است — فقط لایه‌ی ذخیره‌سازی
(Durable Object → Redis) و لایه‌ی شبکه (`cloudflare:sockets`/
`WebSocketPair` → `net`/کتابخانه‌ی `ws`) عوض شده.
